# NosAi — Contributi

## Regole generali

Ogni modifica deve essere coerente con l'architettura e con la versione 1.0 Beta.

## Lingua

La documentazione deve essere scritta in italiano. Codice, identificatori, API e termini tecnici obbligatori possono rimanere in inglese.

## Codice

- mantenere contratti e separazione dei layer;
- preferire comportamenti deterministici sul percorso critico;
- aggiungere test per ogni nuovo comportamento;
- non dichiarare produttivi componenti non validati;
- evitare duplicazione di architetture o servizi già presenti.

## Documentazione

Ogni modifica architetturale deve aggiornare la documentazione interessata e lo stato di implementazione.

## Commit

I messaggi di commit possono usare identificatori tecnici standard quando utili, ma il corpo e la documentazione devono essere in italiano quando possibile.
