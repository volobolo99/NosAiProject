# MCP Chief Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rendere le promozioni del MCP Chief verificabili, lo stato dei binding condiviso e recuperabile, e la suite di test/documentazione coerente con il runtime reale.

**Architecture:** Il Chief resta un'autorità di governance, mai di esecuzione. Un `EvidenceAuthority` locale verifica record firmati e digest prima di consentire una promozione; un `BindingStore` SQLite serializza revisioni, proposte e lease, mantenendo una migrazione compatibile dal JSON esistente. Health e scheduler leggono la stessa sorgente e riportano UNKNOWN quando una misura non è stata osservata.

**Tech Stack:** Python 3.11+, stdlib `sqlite3`, `hashlib`, `hmac`, pytest, JSON Schema già presente, GitHub Actions.

**Spec:** `docs/mcp/RESEARCH_LAB_SPEC.md` e `contracts/mcp-research-lab-001.json`.

## Global Constraints

- Network mode remains opt-in and defaults to disabled.
- Plaintext API keys never enter logs, evidence, dashboard responses, or model context.
- Protected policy, audit, schema, contract, and test paths remain outside Director authority.
- A promotion requires independently verifiable evidence; caller-provided booleans are not evidence.
- Every mutable record carries a monotonic revision and an idempotency-safe transition.
- Existing JSON bindings remain readable and are backed up before migration.
- Offline mode performs no remote provider calls.
- No gameplay urgent path waits for MCP or remote inference.


For Windows-only evidence, run `pwsh -File scripts/validate.ps1` and `dotnet test` on the Windows runner; do not mark it verified from Linux.

Each task changes a bounded set of files and keeps the pre-migration JSON backup. Revert the task commit or restore the recorded binding-store backup if a verification gate fails.
