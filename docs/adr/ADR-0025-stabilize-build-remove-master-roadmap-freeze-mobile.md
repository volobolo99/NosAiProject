# ADR-0025 — Stabilize the build, remove the superseded master roadmap, freeze the mobile channel

**Status:** Accepted
**Date:** 2026-09-05
**Builds on:** [ADR-0015](ADR-0015-adopt-roadmap-esecutiva-as-canonical-architecture.md)

## Context

A repository audit found the solution in a non-buildable state, and found two long-standing documentation contradictions left open by ADR-0015:

1. `src/NosAi.GuardClient/NosAi.GuardClient.csproj` did not exist, even though `tests/NosAi.Runtime.Tests/NosAi.Runtime.Tests.csproj` carries a `ProjectReference` to it and six real test files (`GuardAiClientTests.cs`, `GuardAppLogicTests.cs`, `GuardNegativeTests.cs`, `GameplayWireContractTests.cs`, `GuardAdmissionTests.cs`, `DiscoveryTests.cs`) exercise the real Gate 1 handshake against it. `dotnet restore`/`dotnet test` on that project failed outright. ADR-0015 itself commits to keeping `NosAi.GuardClient` "building with its existing tests green exactly as they are" (`Directory.Build.props`) — this was a regression against that commitment, not a deliberate decision.
2. `NOSAI_MASTER_ROADMAP.md` was marked superseded by ADR-0015 on 2026-09-01 but still sat in the repository root, still linked from `CLAUDE.md`, `CONTRIBUTING.md`, `.cursor/rules/00-nosai-core.mdc`, `docs/AGENT_EXECUTION_CHECKLIST.md`, `docs/AGENT_DEVELOPMENT_ENVIRONMENT.md` and `docs/INDICE_REPO.md` as a document to read before changing code.
3. `NOSAI_ARCHITECTURE_BASELINE.md` §12 declares the product "PC/Windows-first" with smartphone/mobile "removed from the product scope", while the one milestone this project has actually verified on physical hardware (`docs/STATO_IMPLEMENTAZIONE.md`, Gate 1) is precisely the PC↔smartphone Guard AI channel. Neither document reconciled the two statements.

Beyond these three items, restoring an actually-green build surfaced a long tail of independent, pre-existing compilation and test failures across `NosAi.Runtime`, `NosAi.Core.Tests`, `NosAi.ControlPanel.Tests` and `NosAi.Runtime.Tests` — none reachable from any CI run before this point, since no build had completed far enough to reach them. These are implementation bugs, not architectural decisions, and are listed here only as the evidence base for "Verified" below; each is a minimal, root-caused fix (ambiguous duplicate symbols disambiguated, a wrong member name replaced with the correct existing one, missing `using` directives added, a genuinely missing type reconstructed from its call sites, an unwired XAML event handler implemented, two test assertions corrected against verified-correct production behavior) — never a weakened test, a widened mock, or a silenced warning.

## Decision

1. **`NOSAI_MASTER_ROADMAP.md` is deleted**, not merely marked superseded. Its content is fully covered by `docs/ROADMAP_ESECUTIVA.md` (canonical roadmap), `docs/STATO_IMPLEMENTAZIONE.md` (Gate 1-6 implementation status) and this repository's own git history; nothing it recorded is lost. Every reference to it is repointed to `docs/ROADMAP_ESECUTIVA.md`. `src/NosAi.ControlPanel/WorkspaceLocator.cs` used the file's literal name as its repository-root marker; it now uses `NosAi.sln`, which is guaranteed to exist at the root and carries no risk of being retired the way a roadmap document can.

2. **`NosAi.GuardClient` is restored, not deprecated.** A `NosAi.GuardClient.csproj` (plain `net8.0`, `ProjectReference` to `NosAi.Protocol`) now exists matching the layout `src/NosAi.GuardAi.App/README.md` already documented, and is added to `NosAi.sln`. The three types its own source referenced but the repository never defined — `IDeviceSigner`, `DeviceKeyCustody`, `RsaDeviceSigner` — were reconstructed strictly from their call sites in `GuardAiClient.cs`, `KeystoreDeviceSigner.cs`, `DeviceIdentity.cs` and `GuardConnectionService.cs` (interface shape, enum members, both constructor overloads, the SHA-256/PKCS#1 v1.5 signing scheme matching the Android Keystore signer byte-for-byte, and the RSA-2048 validation `GuardAiClientTests.KeysOtherThanRsa2048AreRejectedBeforeAnyTraffic` already asserted). This is the PC-side library the already-verified Gate 1 channel is tested against; restoring it is required by the "never weaken or delete tests" rule, not optional.

3. **`NosAi.GuardAi.App` (the Android/MAUI phone UI) is frozen out of scope, not restored.** It has no `.csproj` in the repository, nothing in the solution or test suite references it by `ProjectReference`, and building it requires a MAUI Android workload this repository's CI does not carry. Per `NOSAI_ARCHITECTURE_BASELINE.md` §12, mobile is out of product scope for the current `AP-00`…`AP-10` roadmap. Its source is kept as historical/reference material (it documents exactly what a phone-side Gate 1 client looks like, and the evidence in `docs/STATO_IMPLEMENTAZIONE.md`/`docs/GATE1_CHECKLIST.md` that the mobile half of Gate 1 was verified on physical hardware stands as recorded history) but is not part of the buildable solution and is not scheduled for further work. **This reconciles the contradiction above by scope, not by fact**: the mobile channel was real and verified once, under the superseded architecture; it is not part of the product going forward.

4. **CI on `ubuntu-latest` no longer attempts to run `NosAi.ControlPanel.Tests`.** That project hosts real WPF windows (`UseWPF`, `src/NosAi.ControlPanel/NosAi.ControlPanel.csproj`) and needs the `Microsoft.WindowsDesktop.App` shared runtime, which has no Linux build at all — the test host cannot launch on any Ubuntu runner regardless of what is installed. `.github/workflows/dotnet-windows.yml` already runs this project's tests on `windows-latest`; the Ubuntu job still builds it, it just no longer tries to execute it where it structurally cannot run.

## Consequences

- The solution restores, builds (`NosAi.Runtime`, `NosAi.Core.Tests`, `NosAi.ControlPanel.Tests`, `NosAi.Runtime.Tests`) and its test suites pass on Linux to the extent the platform allows: `NosAi.Core.Tests` fully; `NosAi.Runtime.Tests` fully except tests that honestly self-skip on non-Windows (`WindowsOnlyFactAttribute`, the same pattern already used by `RuntimeIdentityTests`/`MemoryScannerTests`); `NosAi.ControlPanel.Tests` builds on Linux but only executes on Windows, as it always structurally had to.
- `NOSAI_MASTER_ROADMAP.md` no longer exists at any path. A reader following any of the documents listed in Context now lands on `docs/ROADMAP_ESECUTIVA.md` directly.
- `NosAi.GuardClient` is a normal, buildable, tested project again. `NosAi.GuardAi.App` remains unbuilt source with no CI coverage; a future decision to build it again (e.g. if mobile re-enters scope) needs its own ADR and its own `.csproj`, not a silent revival.
- Nothing in this ADR changes the wire contracts, the Gate 1-6 status recorded in `docs/STATO_IMPLEMENTAZIONE.md`, or any Safety/Guard/Trust boundary. It is a stabilization and documentation-hygiene decision, not a product or architecture change.
