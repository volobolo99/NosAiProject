# ADR-0021 — Unprivileged observability boundary for the university demonstration

**Status:** Accepted
**Date:** 2026-09-04
**Scope:** University demonstration and validation environment

## Decision

NosAi must be fully demonstrable using only information and capabilities available to an ordinary game client/player in the declared private test environment.

The project explicitly does **not** depend on moderator, GM, administrator, developer-console, database-admin, server-admin or privileged-management access to obtain gameplay state or to execute gameplay actions.

The authoritative observation boundary is:

`Network traffic visible to the client + client process memory legitimately readable by the runtime + pixels/input exposed through the client window + NosAi-owned local telemetry`

Anything available only through privileged server-side interfaces is out of scope for the gameplay AI and must never be silently used as a fallback.

## Allowed observation sources

1. **Client-visible network traffic** — traffic that reaches the test client and is observable by the client-side integration layer.
2. **Client process memory** — memory regions of the supported client process that the local runtime can read under the declared test setup. No server database or privileged server memory is required.
3. **Screen/window perception** — screenshots, pixels, window geometry, OCR and computer-vision observations available from the local client display.
4. **Local OS telemetry** — CPU, RAM, GPU, network and process/window telemetry required for runtime safety and diagnostics.
5. **NosAi-owned state** — internal event journal, planner state, agent memory and locally generated metrics.

## Forbidden sources

The following are explicitly prohibited from the gameplay observation path:

- GM/moderator/admin commands or panels used to reveal hidden gameplay state;
- direct server database queries;
- server-side privileged APIs not exposed to an ordinary client;
- administrative packet injection or server-console commands used to manufacture observations;
- privileged server logs containing information unavailable to the ordinary client;
- test-only hidden flags that disclose future, hidden or authoritative state to the agent;
- manually supplied gameplay facts during an autonomous run, except explicit operator intervention recorded as such;
- any secret/admin credential used to enrich the AI's world model.

## Action boundary

Gameplay actions must also be produced through the same non-privileged client-side boundary declared by the experiment. The AI may not call a privileged server API to perform an action that an ordinary client could not perform.

The Safety Gate remains the sole execution authority. LLMs, planners and heuristics propose intents; they never receive direct execution authority.

## Unknown means unknown

If a fact cannot be established from an allowed source, its value is `UNKNOWN` rather than inferred from privileged knowledge.

Planning must skip rules that require an `UNKNOWN` fact. The agent must be able to continue safely with partial observation or stop and report insufficient observability.

## Commission acceptance principle

A demonstration is valid only if the commission can reproduce it from a clean ordinary-player setup using the documented installation and test procedure, without administrator/moderator access to the game server.

The demonstration must record:

- environment and client version;
- data sources active during the run;
- actions requested by the agent;
- safety decisions;
- relevant network/memory/screen observations;
- failures and recovery;
- evidence that no forbidden source was consulted.

## Evidence levels

Every gameplay fact should carry provenance:

- `Network` — observed from client-visible traffic;
- `Memory` — observed from local client memory;
- `Screen` — observed from client pixels/window perception;
- `Local` — generated by NosAi itself;
- `Operator` — explicitly supplied by a human;
- `Unknown` — unavailable from permitted sources.

`Operator` facts are never silently converted into autonomous observations.

## Consequence

The existing `RealClientConnector`, process probes, screen perception and network components remain valid integration mechanisms, but they must converge on this boundary. The project should prefer multiple independent permitted observations when available and expose provenance in the canonical WorldState.

This ADR is a hard architectural constraint for the university release and supersedes any implementation choice that would require privileged server access.
