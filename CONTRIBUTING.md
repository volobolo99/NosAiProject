# Contributing to NosAiProject

## Before changing code

Read `CLAUDE.md`, `NOSAI_MASTER_ROADMAP.md`, `docs/NOSAI_ARCHITECTURE_BASELINE.md` and the relevant ADRs.

## Development cycle

`SPEC → PLAN → IMPLEMENT → BUILD → TEST → REVIEW → VERIFY`

Keep changes focused on one milestone or coherent technical objective.

## Pull requests

Include the milestone/task ID, behavioral change, architecture impact, tests/build performed, security impact and remaining risks.

## AI-assisted development

AI-generated code is subject to the same review and testing requirements as human-written code. Agents must not claim real-environment verification without evidence and must stop when an architectural decision is ambiguous.

## Definition of Done

A change is `DONE` only after implementation, build, relevant tests and documentation are complete. It is `VERIFIED` only after its integration/real-environment acceptance criteria have been satisfied.
